# 補助金レジストリ 四半期チェック手順

## 目的

受付終了・予算消化・要件改定を検出し、原典確認なしの情報を公開しない。四半期ごと（1月・4月・7月・10月）の運用タスクとする。年度更新は4月回に集約する。

## 手順

1. `npm run collect:sources -- source-manifests/YYYY-MM-DD.json` を実行し、3源（すまいづくりまちづくりセンター連合会、アットホーム空き家バンク、競合差分）の取得日時・HTTP結果・ハッシュを保存する。
2. 前回マニフェストとの差分を確認し、制度名・上限・対象・要件・受付期間が変わった候補を `pending` に戻す。競合サイトは発見用であり、公開原典にはしない。
3. 各候補の自治体公式ページ・要綱・募集要領を人間が開き、`originalUrl`、`checkedOn`、上限、対象、要件、受付状況を照合する。
4. 検証者は `docs/verification-log.md` に候補ID、原典URL、確認日、判定、差分、証跡を記録する。判定前の候補は `publication_status=preview` のままにする。
5. 承認した候補だけを InsForge の ledger に新しい行として追加し、`human_review_status=approved` と `publication_status=published` にする。既存行の上書き・削除は禁止し、変更は `supersedes_id` で履歴化する。
6. `npm run validate:registry`、`npm run build` を実行し、47ハブ・初期20市・公開ゲート制約を確認する。
7. 実行日時、担当者、未解決候補、次回期限を運用ログに追記する。

## 4月の年度一括

年度切替では全制度の受付期間・予算枠・要綱を再確認する。前年度行は `valid_to` を設定し、新年度の原典確認済み行を追加する。前年度URLを新年度の原典として流用しない。

## 人間スポット検証の最低条件

- 初回公開前に20市すべてを確認し、以後は毎回ランダム10%以上を再確認する。
- `originalUrl` が自治体・国等の原典でない候補は公開しない。
- 上限・受付中・対象工事の一つでも原典で確認できない候補は `held` にする。
- 競合サイトやLLM出力だけで `approved` にしてはならない。
